# 「最初の一冊」診断ツール 設計

- 日付: 2026-08-16
- 対象: senso-wo-yomu.com（昭和の戦争を読む・64冊）
- 目的: 「戦争のことを知りたいが、何から読めばいいか分からない」人を、適切な1冊へ導く

## 背景

サイトは64冊を3軸（出来事・著者の方法論・視点）で俯瞰できるが、初訪問者にとっては情報量が多い。
俯瞰マトリクスは「全体を見たい人」の道具であり、「最初の1冊を選びたい人」の道具ではない。
この非対称がサイトの入口の弱点であり、それを埋めるのが本ツール。

## 設計判断（承認済み）

| 論点 | 決定 | 理由 |
|---|---|---|
| 診断の起点 | **動機**（なぜ知りたいか） | 初心者は出来事名（ノモンハン・レイテ）を知らないため、出来事から聞くと答えられない。動機なら知識ゼロでも答えられる |
| 出力 | **1冊＋次の1冊** | 3冊並べると「どれを選ぶか」の元の問題に戻る。主役を1冊に絞り、次の1冊で道すじを示す |
| 質問構成 | **3問**（動機→読み口→量） | 動機だけでは同じ動機の人が全員同じ本になる。3問で30秒、サイトの3軸をそのまま使える |
| 推薦方式 | **スコアリング**（決め打ち表でない） | 6×4×2＝48通りを手で埋めるのは非現実的。新刊追加時に自動で候補入りする |

## URL・名称

- パス: `/guide/`
- 名称: 「最初の一冊」
- 結果はクエリで保持: `/guide/?m=<動機>&r=<読み口>&v=<量>`（ブックマーク・共有可能）

## 質問設計

### 問1: なぜ知りたいか（6択）→ events・viewpoints の重みを決める

| id | 選択肢 | 重み付け先 |
|---|---|---|
| `kazoku` | 親や祖父母が生きた時代を知りたい | events: kushu, sengo, tsushi ／ viewpoints: jugo, kodomo |
| `naze` | なぜ始めて、なぜ止められなかったのかを知りたい | events: kaisen, manshu, tsushi ／ viewpoints: seisaku |
| `senjo` | 戦場で兵士に何が起きたのかを知りたい | events: nanpo, leyte, okinawa ／ viewpoints: heishi |
| `shimin` | 空襲や原爆の下で、市民がどう生きたかを知りたい | events: genbaku, kushu ／ viewpoints: jugo, kodomo, josei |
| `soshiki` | なぜあんな作戦が通ったのか——組織の失敗として学びたい | events: nomonhan, midway, tokko ／ viewpoints: shiki, seisaku ／ method: soshiki に加点 |
| `gaichi` | 外地からの引揚げや、植民地支配のことを知りたい | events: sengo, nicchu ／ viewpoints: shokuminchi, josei, horyo |

### 問2: どう読みたいか（4択）→ method の重みを決める

| id | 選択肢 | 重み付け先 |
|---|---|---|
| `monogatari` | 物語として、通して読みたい | methods: jojutsu, kiroku |
| `honnin` | 体験した人自身の言葉で読みたい | methods: shuki, shogen |
| `shiryo` | 史料と数字で、確かめながら読みたい | methods: jissho, soshiki |
| `karui` | 漫画や詩など、活字が重くない形で | 特定書籍（漫画・詩）に直接加点 = `light: true` フラグ |

### 問3: どのくらいの重さか（2択）→ level の重みを決める

| id | 選択肢 | 重み付け先 |
|---|---|---|
| `karume` | まずは軽いものから | level 入門に加点、専門に減点 |
| `atsume` | 厚くても、読み応えがある方がいい | level 中級・専門に加点 |

## スコアリング

```
score(book) =
    3 × (問1の events に book.events が一致した数)
  + 2 × (問1の viewpoints に book.viewpoints が一致した数)
  + 4 × (問2の methods に book.method が一致した場合)
  + 5 × (問2が karui かつ book.light === true)
  + levelScore(問3, book.level)
  + tieBreak(book)   // 同点時の決定用の微小値（配列順）
```

- `levelScore`: karume → 入門+3／中級0／専門−3、atsume → 入門0／中級+2／専門+3
- 入手困難な本（`availNote` に「入手」を含む）は −2（最初の1冊として薦めにくいため）
- `related: true` の本（『戦略の本質』＝外国戦史）は候補から除外

### light フラグ（問2「活字が重くない形で」用）

以下の書籍に `light: true` を付与する：
`comic-showa-shi`／`soin-gyokusai-seyo`／`hadashi-no-gen`／`kono-sekai-no-katasumi-ni`／`genbaku-shishu`

## 結果画面

1. **まずこの1冊** — 書影（既存の.coverコンポーネント）＋書名＋著者＋方法論チップ＋紹介文＋書籍ページへのリンク
2. **なぜこの本か** — 回答から1文を生成（例: 「体験した人の言葉で、空襲や原爆の下の暮らしを知りたいあなたに」）
3. **読み終えたら次はこれ** — 推薦書の「対で読む」相手を1冊。存在しない場合は同じ出来事の別方法論から最高得点の1冊
4. **もう一度診断する** ボタン
5. 俯瞰マトリクスへの導線（「全体を見たい方はこちら」）

## 技術

- Astro の静的ページ `src/pages/guide.astro`
- 書籍データはビルド時にJSONとしてページへ埋め込む（63冊・軽量）
- 診断ロジックはクライアントサイドJS（サーバー不要）
- 既存CSS（紙とインク様式）を流用。新規スタイルは最小限
- `prefers-reduced-motion` を尊重

## 導線

- トップページ: 「三つの入口」セクションの**上**に配置（初訪問者が最初に見る位置）
- ヘッダーナビに「最初の一冊」を追加
- sitemap に自動で含まれる

## 非目標（YAGNI）

- 診断結果の保存・ユーザーアカウント
- 「あなたは○○タイプ」の人格ラベル（戦争を扱うサイトのトンマナと衝突）
- 3冊以上の同時提示
- サーバーサイド処理・アクセス解析による推薦の学習
